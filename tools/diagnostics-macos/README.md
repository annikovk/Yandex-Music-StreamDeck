# Сбор диагностики DOM Яндекс Музыки (macOS)

Этот скрипт нужен, чтобы понять, почему на конкретной странице Яндекс
Музыки кнопки Stream Deck не работают. Он раз в секунду снимает DOM
страницы и сохраняет каждый снимок в JSON-файл.

Скрипт написан на встроенном в macOS Perl — **ничего устанавливать не
надо**. Открывается двойным кликом, как обычный документ.

## Что внутри
- `dump-ym-dom.command` — двойной клик, запускает сбор.
- `dom-dumps/` — сюда падают снимки (папка создастся автоматически).

## Как пользоваться

1. **Запусти Stream Deck.** Убедись, что плагин Yandex Music уже
   стартанул Яндекс Музыку (приложение должно быть открыто). Плагин
   запускает её с флагом отладки `--remote-debugging-port=9339`, к
   этому порту скрипт и подключается.

2. **В Яндекс Музыке открой ту страницу, где кнопки не работают.**
   Например, **Моя Волна / My Vibe**.

3. **Двойным кликом запусти `dump-ym-dom.command`.** Откроется Terminal
   и начнётся сбор. Каждую секунду в папку `dom-dumps/` будет падать
   новый файл `dump-YYYYMMDD-HHMMSS-fff.json`.

   Если macOS скажет «**не может быть открыт, потому что разработчик не
   проверен**» (Gatekeeper защищает .command файлы из интернета), кликни
   правой кнопкой по `dump-ym-dom.command` → **Открыть** → подтверди.
   Это нужно сделать только один раз.

4. **Прямо во время сбора** попробуй нажать кнопки на Stream Deck (или
   соответствующие кнопки в самом приложении: play/pause, like, mute,
   next, previous). Это нужно, чтобы в снимках было видно, как DOM
   меняется при действиях.

5. **Через 30–60 секунд** останови сбор: **Ctrl+C** в окне Terminal.
   Скрипт скажет, сколько снимков собралось и где они лежат.

6. **Заархивируй папку `dom-dumps/` в ZIP** (правой кнопкой → Compress)
   и отправь архив обратно.

## Если что-то пошло не так

- **«cannot reach Chrome DevTools Protocol on port 9339»** — значит,
  Яндекс Музыка не запущена через плагин. Запусти Stream Deck, дай ему
  пару секунд стартовать приложение, и попробуй снова.
- **«no music-application page target found»** — порт открыт, но это
  не Яндекс Музыка. Скорее всего, приложение запущено вручную без
  флага отладки. Закрой его полностью и дай плагину перезапустить.
- **macOS блокирует .command** — `xattr -d com.apple.quarantine
  /путь/к/dump-ym-dom.command` в Terminal снимает блокировку. Или
  правый клик → Открыть из Finder.
- **Файлы получаются большими (1–3 МБ каждый)** — это ожидаемо, в них
  лежит полный HTML страницы. ZIP сожмёт всё это в 5–10 раз.

## Что в каждом снимке

```jsonc
{
  "timestamp": "2026-05-15T10:17:57.120Z",
  "url": "music-application://desktop/",
  "title": "Яндекс Музыка",
  "viewport": { "w": 1280, "h": 800 },
  "testIds": [
    // Каждый элемент с data-test-id — тег, классы, позиция, sprite-ссылки,
    // aria-атрибуты, обрезанный textContent
  ],
  "playerBarCandidates": [
    // Кандидаты на «плеер-бар» по подстрокам в class
    // (PlayerBar, playerBar, Player_, Vibe ...)
  ],
  "html": "<html>... весь DOM ...</html>"
}
```

Информации в `testIds` и `playerBarCandidates` обычно хватает, чтобы
понять, по каким селекторам теперь искать кнопки на новой странице.
